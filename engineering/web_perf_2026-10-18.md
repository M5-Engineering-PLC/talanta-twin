## Evidence and target

All results below are software results. There are no physical measurements, browser timings, or GPU measurements in this review.

The target is 30 FPS at 1366×768 on an Intel UHD 620 class laptop. This is an estimate, not a measured result. Its frame budget is about 33.3 ms. Munene reported 7 FPS at sunset before this work. That report is not a controlled baseline for these changes.

The Kenyan Historian footage decides geometry, layout, and detail. The 06 and 07 concepts guide light, color, haze, and composition only. If they disagree, the footage wins. This patch changes seat detail by quality tier. Seat positions, aisles, tier shapes, and site geometry stay unchanged. No reference image becomes a texture.

## Opening time and hero selection

The procedural view opens at 07:30 EAT on the current EAT date. `?time=07:30` and `?time=450` select minutes after EAT midnight. Invalid values use 07:30. The time control overrides the opening value. Playback, date changes, and manual time changes disable the live clock.

The Live clock button toggles the current EAT date and minute. The button starts off. Live time refreshes once per minute and updates the date controls at midnight.

With `?hero`, the app tries `./models/manifest.json` first. If that manifest is absent or invalid, it tries `./models/test/manifest.json`. If neither export loads, the procedural view remains available. A valid full manifest with failed model files falls back to the procedural scene. It does not silently switch to a test model.

Hero loading preserves the UI time, including URL values and changes made during loading. The baked model retains its baked light. Changing the UI clock does not rebake or relight that model. No models directory exists in this checkout, so actual export loading remains untested.

## Geometry profile

A draw call submits one mesh batch to the GPU. Instancing draws many copies through one batch. The existing seats already use one instance batch, so the seat cut saves triangles rather than draw calls.

The following counts come from CPU construction of the bundled data. Canvas drawing was stubbed, and no renderer or browser opened. Counts precede camera culling, shadow passes, and postprocessing. They are derived counts, not estimated GPU timings. High and medium crowd rows describe Match day in daylight. Crowd otherwise remains unbuilt. Bowl counts exclude seats.

The high tree count uses all 55,398 available trees, below its 60,000 cap. Medium uses 18,000 trees, and low uses 4,000 trees. Candidate shadow counts include the daylight crowd and proxy traffic. The shadow frustum removes candidates, so these are not measured shadow submissions.

Traffic counts use 1,200, 180, and 40 vehicles. The profile suppresses the asynchronous vehicle model request to count procedural proxies only. Near nganya models add geometry and material batches. Their costs depend on camera distance and model loading, and remain unmeasured. `traffic.js` computes its current draw and triangle counts in `group.userData`.

The seeded crowd contains 51,339 high-tier fans and 12,836 medium-tier fans. Night phones add one call and 18,480 high-tier triangles or 4,620 medium-tier triangles. Low builds no crowd. The existing crowd statistics include the hidden phone batch, which explains their daylight call count of eight versus seven visible calls.

The three unchanged terrain grids add three calls and 815,606 triangles before culling on every procedural tier. Low totals about 1.68 million triangles for the listed parts plus terrain. That subtotal excludes the pitch, training sport, boundary, sky, highlights, and labels. It is not a complete scene budget or a frame-rate prediction.

`PROFILE_BY_TIER` in `perf.js` records this source snapshot with claim fields and CPU notes. `profileGeometry(root)` counts geometry before culling without rendering. `window.__twin.performanceProfile()` exposes current subtree counts for later device testing. Its bowl subtree includes seats, so do not add its seat row twice. Its context row contains trees, with buildings and roads in separate rows.

## CPU work per frame

| Part | High | Medium | Low | Claim |
|---|---|---|---|---|
| Seats | No matrix writes | No matrix writes | No matrix writes | derived from code |
| Bowl | State mutations only when construction state changes | Same | Same | derived from code |
| Context | Static meshes, tree instances, traversal, culling | Same, fewer instances | Same, fewer instances | derived from code |
| Site | 73 jet calculations, 146 jet/cap matrix writes, 40 walker matrix writes | Same | Same, but scale people stay hidden | derived from code |
| Traffic | Sort lanes and update 1,200 vehicles | Sort lanes and update 180 vehicles | Sort lanes and update 40 vehicles | derived for fresh startup |
| Crowd | Three uniforms, 25 player transforms, 75 player matrix writes | Same CPU loop, fewer GPU fans | No build or update | derived from code |
| Shadows | Caster traversal and one directional shadow pass | Same with smaller map and range | Disabled | derived from code |

The site update also changes water UV offsets, fountain materials, and lamp intensity. Hero mode and hidden furniture skip the whole site update. GPU shaders animate fans and flags. The crowd figures, traffic, and grade are visualizations, not validated safety simulations.

Traffic sorting costs approximately O(N log N). This notation describes growth with vehicle count, not milliseconds. The existing `setLimit()` hides vehicles but still sorts the original fleet and writes its instance slots. Therefore, a downgrade from high does not obtain the same CPU saving as a fresh low startup. The traffic worker owns that implementation. This patch calls the existing method and does not change it.

The sun and sky now update only when the date or minute changes. The sky contains 561 vertices. Previously the loop repainted its colors every frame and repeated the solar calculation. At 30 FPS with a fixed clock, the patch avoids about 16,830 sky color writes per second after the first update. This is a derived operation count, not a CPU timing. Construction updates also use a state key. Controls, labels, charts, traffic, and the frame-rate monitor still do per-frame work.

## Cuts and expected savings

| Change | Before | After | Expected saving and evidence |
|---|---|---|---|
| Low seats | 36 triangles per seat | One two-triangle surface per seat | 1,937,048 triangles, 94.4%, derived. same one draw call |
| Medium seats | Pan, back, leg, 36 triangles | Pan and back, 24 triangles | 683,664 triangles, 33.3%, derived |
| Low matchday crowd | Fraction 0.2 | Fraction 0 | All fan, flag, phone, and player work removed. roughly 0.59 million daylight triangles, estimated prior population |
| Medium matchday crowd | Fraction 0.5 | Fraction 0.25 | Approximately half the former fan geometry, estimated. CPU player loop unchanged |
| Low scale people | 276 visible figures | Hidden | One call and 30,912 triangles, derived. existing site walking updates remain |
| Low traffic startup | 150 vehicles | 40 vehicles | 73.3% fewer vehicles, derived. similar sorting and geometry savings are estimates |
| Medium traffic startup | 500 vehicles | 180 vehicles | 64% fewer vehicles, derived. similar sorting and geometry savings are estimates |
| Traffic downgrade | Existing fleet | Existing `setLimit()` | Fewer visible vehicles. no claim that sorting work falls |
| Medium shadows | 2048² map, ±420 extent, far 4000 | 1024² map, ±300 extent, far 2300 | 75% fewer map texels, derived. caster and timing savings depend on view |
| High shadows | 2048² map, far 4000 | Same map, far 2600 | Smaller depth range. no guaranteed triangle or timing saving |
| Low shadows | Disabled | Disabled, tier metadata 512², ±240 extent, far 2100 | No new saving. no map allocation while disabled |
| High pixel ratio cap | 2 | 1.5 | Up to 43.75% fewer pixels on high-DPI screens, derived |
| Medium pixel ratio cap | 1.5 | 1.25 | Up to 30.6% fewer pixels on high-DPI screens, derived |
| Low pixel ratio cap | 1 | 1 | Retained 1366×768 native budget of 1,049,088 pixels. no new saving |
| Idle sun and sky | Every frame | Only after time changes | Avoid repeated solar work and 561 color writes per unchanged frame, derived |
| Hidden site animation | Every frame | Skipped while hidden or in hero mode | Avoid 186 matrix writes per skipped frame, derived |
| Low startup detection | Generic backend score | Conservative laptop hint | Avoid initial high allocation for the target class. timing saving unmeasured |

The laptop hint selects low when reported memory is at most 8 GB, threads at most eight, and screen width at most 1600. It does not identify a GPU. `?tier=` overrides the hint, and `?lite` forces low. The existing monitor still downgrades after four seconds below 28 FPS.

Seat matrices and instance colors remain allocated, so startup storage does not fall with triangle count. They use 4,329,872 bytes across all tiers, excluding object overhead and geometry. High-tier seat geometry remains unchanged. Lower tiers share the existing placement loop and replace only their seat geometry. No full-tier seat rewrite was necessary.

Tree and terrain budgets remain unchanged. The table records them because they remain substantial costs. Automatic tree downgrades thin existing batches and can produce lower counts than a fresh startup. Postprocessing remains high-only and follows the existing `?nopost` switch.

## Hero look

The high-tier grade adds modest warmth to highlights and a small lift to green-dominant surfaces. Saturation changes from 1.04 to 1.055. Warmth changes from 0.018 to 0.025. These values are estimated artistic choices. The bake remains the main source of the look.

Hero haze starts at 2200 m and reaches full density at 16000 m, with the panorama horizon color when available. These distances are estimated artistic values. The haze uses the normal material fog path on every tier. Medium and low retain their cheaper path without the full grade or postprocessing.

No browser opened, so this review does not establish a visual match against the cloud stills. The GPU shader graph was constructed in software but was not compiled on a GPU.

## Public interfaces and integration

The added or extended interfaces are:

- `openingMinutes(value)` returns opening minutes after EAT midnight.
- `buildBowl(features, opts = {})` accepts `opts.tier` and returns `setTier(tier)` alongside existing fields.
- `profileGeometry(root)` returns `{ claim, drawCalls, triangles }` before culling.
- `PROFILE_BY_TIER` provides the dated source profile for each tier.
- `applyHeroHaze(scene, horizon)` installs and returns the hero fog.
- `heroGrade(inputNode, opts = {})` accepts the added `greenery` value.
- `window.__twin.performanceProfile()` returns the current geometry counts for later device work.

`buildCrowd()` keeps its signature and exits before allocation when fraction or occupancy is zero.

No cloud hook lines are required. The cloud exporter must place the production manifest and its existing model files under `app/public/models/`. Test exports remain under `app/public/models/test/`. The existing loader contract remains unchanged. No Blender file needs an edit for this patch.
